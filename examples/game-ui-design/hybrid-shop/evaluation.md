# Evaluation approach

This exercise explicitly requests the image and hybrid routes. It does not test automatic route selection. Both branches receive the same written shop brief and use the same Godot native-input tests, initial coins, prices, and stock. Both may inspect their actual running screens and correct defects. The direct builder is not given the generated concept or earlier test designs.

Compare three judgments separately:

- Design quality: readability at normal play size, compact controls, clear purchase hierarchy, and fit to the assumed cozy storybook art direction.
- Fidelity: how the hybrid's native Controls and illustration preserve the chosen SVG composition, and which elements intentionally change from the generated concept.
- Function: native mouse/keyboard focus, selection, purchases, stock and affordability, and content bounds at both sizes.

This is one qualitative example. Art style, available assets, elapsed time, token budgets, agent behavior, and revision effort are not controlled. A more detailed generated illustration alone does not establish that its layout or interactions are better. There is no numeric aesthetic score.

The original generated concept is preserved. The hybrid mockup deliberately uses smaller type and a 160x48 purchase action instead of copying the concept's larger controls literally. Illustration assets remain separate from live labels, wallet, prices, stock, selected state, and input controls. Before/after evidence is retained when a render-driven correction is made.
